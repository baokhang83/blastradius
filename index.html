Run the tests a change can reach. Skip the rest.

Blastradius learns which production classes each test really loads, then narrows a pull request’s test run to the tests that could be affected. No server, no model to train: a saved map and explicit rules you can read in the build log.

How it works — click through it

One engine, three build modes decided fresh on every run. Pick a mode, then click any stage.

What it measured

200 consecutive commit pairs on each of four open-source projects, with injected-fault (mutation) validation on the same run. These are selected test executions, not CI wall-clock time.

Start in a minute

<plugin>
  <groupId>io.github.baokhang83.blastradius</groupId>
  <artifactId>blastradius-maven-plugin</artifactId>
  <version>0.4.0</version>
  <executions><execution>
    <phase>process-test-classes</phase>
    <goals><goal>select</goal></goals>
  </execution></executions>
  <configuration><baseRef>main</baseRef></configuration>
</plugin>

Selection is sound by default, not by guarantee. Keep a regular (recommended: daily) full-suite run as the backstop. The Gradle plugin is in the repository; Plugin Portal publication is pending.
