Blastradius vs Develocity PTS vs Smart Tests

Three different ideas of “which tests should this change run?” Observed dependencies, a trained model, and an LLM plus history. Here is how they differ, and when each one wins.

Summarised from each vendor’s public documentation on 2026-11-15; linked below. This is not a benchmark and not a compatibility guarantee. Products change: check current docs and validate on your own suite.

When to pick something else

  • You already run Develocity. PTS reuses the Build Scan data you already collect, supports both build tools today, and has a simulator to estimate savings first.
  • You need many languages or test frameworks. Smart Tests is not tied to the JVM or JUnit 5; Blastradius is.
  • You want dashboards, flaky-test analytics or a managed service. Blastradius intentionally has none of these.
  • You need a Gradle plugin from the Plugin Portal today. Not yet available for Blastradius.

When Blastradius fits

  • You want an open-source tool with no server and no data leaving your CI.
  • You want each skip to be traceable to a rule, not a score.
  • You can run a trunk build that writes an index and cache it for pull requests.
  • You accept the known limits: string-dispatched APIs, reflection and generated calls can escape attribution, so keep a daily full run. See validation.
